# Итоговое ревью интеграции

Шаблон для `j-critic` после выполнения задач. Область шире ревью одной задачи:
проверяй совместную работу изменений относительно требований. Политика процесса
задана в [SKILL.md](../SKILL.md) и правилах проекта.

## Вход

`[PLAN_OR_REQUIREMENTS]`, `[PROJECT_RULES]`, `[GLOBAL_CONSTRAINTS]`, `[LEDGER_FILE]`,
`[RESULT_FILES]`, `[DIFF_FILE]`, `[DIFF_SCOPE]` (исходный BASE, коммиты либо пути рабочего
дерева и ограничения изоляции), `[REVIEW_RESULT_FILE]`.
Контроллер отдельно указывает отложенные замечания и принятые решения из журнала.

## Проверка

1. Покрытие требований и приёмки всем набором задач, обоснованность отклонений.
2. Согласованность интерфейсов и данных между компонентами, публичное поведение,
   обработка ошибок и существенные границы.
3. Безопасность, совместимость, миграции, производительность и документация,
   когда изменения затрагивают эти области.
4. Полезность тестов, достаточность доказательств для проверенной версии и реальные
   пробелы интеграции. При изменении тестов используй [writing-good-tests.md](writing-good-tests.md).
   Не повторяй подтверждённые прогоны неизменённого кода/окружения без конкретной причины.
5. Отложенные и спорные замечания: допустимы ли они для готовности всего результата.

Можно читать окружающий код и точечные зависимости. Не меняй checkout, индекс, HEAD,
ветки и чужой runtime. При необходимости нового теста согласуй запуск с контроллером.
Отчёт пиши только по предоставленному пути; других агентов не вызывай.
Недоступные материалы и смешанные изменения обозначь как ограничения проверки.

## Результат

- **Соответствие требованиям:** выполнено/пробелы/не проверено с доказательствами.
- **Замечания:** `Critical | Important | Minor`, файл:строка, дефект, последствие,
  исправление при необходимости. Личный стиль и предположительные будущие требования
  не являются блокирующими дефектами.
- **Отложенное:** какие пункты журнала допустимы, какие препятствуют готовности.
- **Готовность к приёмке:** `Ready | Needs fixes | Verification incomplete` с основанием.
- **Проверки и ограничения:** фактический охват, выполненные команды и недостающие доказательства.

Полный результат в `[REVIEW_RESULT_FILE]`, в ответе статус и путь.
Вердикт ревью не является разрешением на merge, push или публикацию.
