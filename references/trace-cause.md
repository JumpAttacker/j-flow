# Найти источник неверного значения

Этот приём нужен, когда ошибка видна поздно, а значение проходит несколько границ.
Зафиксируй первый наблюдаемый неправильный результат и ожидаемый контракт.
Проследи переданное значение назад: где оно получено, преобразовано и впервые
стало неверным. Для каждой границы сохрани фактический вход и выход без лишних секретов.

Проверь альтернативные источники и условия: прежнее состояние, общий файл, порядок
вызовов, нестабильность среды. При поиске загрязняющей проверки запускай изолированный
целевой случай и части предшествующей последовательности средствами реального раннера.
Ноль найденных/выполненных тестов и ошибка запуска не считаются чистым результатом.
После локализации вернись к разбору причины и воспроизводимой проверке исправления.
