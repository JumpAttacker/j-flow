# Подготовить решение

На старте контроллер устанавливает конкретный проект, желаемый результат и фактическую
точку начала. Источники: правила, описание, state, затронутые функции и доступная реализация.
Недостающую карту создаёт по [project-documentation.md](project-documentation.md).

Выбери масштаб по изменению:

| Ветка | Для чего | Результат |
|---|---|---|
| spike | Снять неопределённость подхода | Вывод и доказательства |
| bounded | Изменить понятный участок существующего поведения | Изменение с приёмкой |
| architectural | Создать или изменить существенные связи и ответственность | План, задачи и проверка целого |

Исследуй область решения; широкое чтение существующего проекта назначь разведчику.
Противоречащие названия понятий уточни на конкретном примере, принятую формулировку
сохрани в описании проекта. Вопросы собирай по влиянию на результат и проверку;
очевидный выбор делай сам в разрешённых границах.

Сравни существенные варианты через последствия для пользователя, модулей и проверки.
UI получает варианты дизайнера до согласования; исследовательские материалы сохраняются
отдельно от внедрения. Состав одобряемого решения и полномочия определены в SKILL.md.
Переход к исполнению допустим после согласования решения; при смене результата обнови его явно.
