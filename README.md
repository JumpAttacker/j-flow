# j-flow

j-flow помогает агенту вести разработку от уточнения задачи до проверки результата.
Перед кодом человек согласует решение и критерии готовности. Затем агент выполняет
работу, привлекает роли для ревью и проверки, сохраняет состояние проекта для следующей сессии.

Скилл подходит для новых функций, изменений архитектуры, существенных изменений
интерфейса и сложных исправлений в конкретном программном проекте.
Мелкие правки, обычные исследования, покупки и бытовая диагностика выполняются напрямую.

## Установка через skills

Требуются Node.js, `npx` и Git. Команда выбирается по агенту:

```bash
# ZCode
npx skills add JumpAttacker/j-flow --skill j-flow -g -a zcode

# Claude Code
npx skills add JumpAttacker/j-flow --skill j-flow -g -a claude-code

# Codex
npx skills add JumpAttacker/j-flow --skill j-flow -g -a codex
```

Пакет включает семь ролей. Если они ещё не зарегистрированы в оболочке,
контроллер читает их инструкции из `roles/` и передаёт доступному общему субагенту.
При отсутствии делегирования агент выполняет работу самостоятельно и сообщает,
что независимого ревью не было. Скилл не создаёт отсутствующие инструменты.

Для установки только в текущий проект из команды убирается `-g`.
CLI `skills` устанавливает файлы скилла; регистрация именованных ролей выполняется отдельно.

## Именованные роли

После глобальной установки можно зарегистрировать роли выбранного агента.
Команды работают в Bash и PowerShell:

```bash
node "$HOME/.zcode/skills/j-flow/scripts/install-roles.mjs" --agent zcode
node "$HOME/.claude/skills/j-flow/scripts/install-roles.mjs" --agent claude-code
node "$HOME/.codex/skills/j-flow/scripts/install-roles.mjs" --agent codex
```

Установщик берёт инструкции из этого пакета, подставляет фактический путь к ресурсам
и записывает семь файлов в каталог агентов. Модель наследуется от сессии.
Настройки MCP и основной конфигурационный файл агента не меняются.
Новая сессия подхватит зарегистрированные роли; в ZCode также доступно обновление списка в настройках.

Проверка без записи: `--dry-run`. Если существующая роль отличается и установщик
её не создавал, установка останавливается до записи файлов. При осознанной замене
используется `--force`: прежние файлы сохраняются в `$HOME/.j-flow-backups/`.
Параметр `--home <абсолютный путь>` позволяет проверить установку в отдельном профиле.

## Использование

В каталоге проекта агент получает запрос:

```text
$j-flow Добавить восстановление пароля. Прочитай AGENTS.md и текущее состояние проекта.
```

В оболочках со slash-командами доступен `/j-flow`. Процедура допускает выбор скилла
по контексту разработки, если оболочка поддерживает автоматическое подключение.

Основная сессия остаётся контроллером. Она выбирает масштаб работы, задаёт вопросы,
показывает решение и критерии готовности. После согласования выполняет работу до приёмки.
Для нового проекта состояние создаётся по [onboard.md](onboard.md).

Документы выбираются по таблице условий в [SKILL.md](SKILL.md#ресурсы-по-ситуации).
Контроллер читает маршрут текущего этапа, а роль получает свой бриф и нужный шаблон.
Справки по поиску причины, защите границ и асинхронным ожиданиям подключаются при
соответствующем симптоме. Чтение всего `references/` не является обязательным шагом.

Тестовая политика и разрешения передаются из правил конкретного проекта.
Отдельная e2e-методология человека-тестировщика относится к назначенной ей работе;
она не становится правилом всех тестов разработчика. Роль `j-tester` исполняет
приёмку задачи и сама по себе не обозначает такой специализированный процесс.

| Роль | Работа |
|---|---|
| `j-scout` | Исследует существующий код |
| `j-designer` | Готовит варианты экрана и проверяет результат по скриншотам |
| `j-implementer` | Выполняет задачу, пишет код и тесты |
| `j-reviewer` | Проверяет отдельную задачу |
| `j-critic` | Независимо проверяет план и результат всей ветки |
| `j-tester` | Исполняет согласованные проверки и собирает доказательства |
| `j-keeper` | Сохраняет состояние и описание фич |

Файлы `.j-flow/state.md` и `.j-flow/features/README.md` помогают продолжить работу
в новой сессии. Спеки и планы сохраняются в `.j-flow/`; доказательства проверок
и временные материалы исключаются из Git.

Полная процедура находится в [SKILL.md](SKILL.md), схема в [diagrams/j-flow-v2.svg](diagrams/j-flow-v2.svg).
Ответы человеку и документы по умолчанию на русском, служебные задания агентам на английском.
Правила конкретного проекта определяют команды, расположение файлов и требования к работе.

## Обновление

```bash
npx skills update j-flow -g
```

После обновления пакета повторяется команда регистрации ролей, если они устанавливались.
Установщик обновляет свои файлы. Перед сохранением личных изменений установленную
роль следует скопировать под другим именем: повторная регистрация заменяет управляемые файлы.

## Инструменты и ограничения

Оболочка должна уметь читать и изменять файлы, выполнять команды проекта.
Для независимых ролей нужны субагенты. Для визуальной приёмки нужен браузерный
инструмент, а для замеров CLS и accessibility нужны соответствующие средства проверки.
Скилл сообщает о недоступных проверках и не объявляет их пройденными.

Дополнительные скиллы для дизайна, `landing-lab`, ContextHub и MCP-каталог `libs`
подключаются отдельно. Их отсутствие не мешает установке j-flow.
Вспомогательные скрипты в `scripts/` требуют Bash, Git и GNU coreutils (`realpath -m`);
в Windows подходит Git Bash. Они вызываются через `bash`, поэтому проектная копия
не зависит от executable-бита. `review-package` умеет собирать диапазон коммитов
и явно перечисленные изменения рабочего дерева, включая новые файлы.
Сам установщик ролей требует только Node.js.

Повторная сборка working-tree-пакета для тех же BASE и путей заменяет его файл.
Перед раундом исправлений сохраняется отдельная копия пакета и исходных версий файлов;
помощник не определяет принадлежность чужих изменений в общем файле.

В `hooks/session-start.mjs` есть необязательная стартовая подсказка для оболочек,
которые поддерживают формат Claude SessionStart. Установка через `skills` не подключает этот хук.

Проверка файлов установки не равна полному прогону разработки в ZCode, Claude Code или Codex.
Результаты таких прогонов фиксируются отдельно.

## Разработка пакета

```bash
git clone https://github.com/JumpAttacker/j-flow.git
cd j-flow
node --test scripts/*.test.mjs
node scripts/install-roles.mjs --agent zcode --dry-run
```

Для изолированной установки к последней команде добавляется `--home` с абсолютным
путём к отдельной папке.
`roles/j-*.md` содержит исходники ролей. `@J_FLOW_ROOT@` в их теле заменяется
путём к установленному скиллу. `scripts/install-roles.mjs` формирует Markdown
для ZCode и Claude Code либо TOML для Codex.
