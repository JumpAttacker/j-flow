# Выбрать полезные тесты

Автор проверки связывает каждый случай с пользовательским результатом, контрактом
или известным риском. Границы, ошибки и отрицательные сценарии выбираются по последствиям.
Проверяй видимое поведение через рабочий интерфейс; изменение внутренней структуры
при сохранении контракта не должно ломать проверку само по себе.

Изоляция исключает чужие данные и общий изменяемый runtime. Замены зависимостей
нужны там, где реальная зависимость недоступна или мешает воспроизводимости;
интеграция с ней получает отдельную проверку и честно названное ограничение.
Асинхронная проверка ждёт наблюдаемое состояние и имеет ограничение времени.

Перед добавлением случая объясни, какой дефект он обнаруживает. Случай, повторяющий
текущий код без проверки внешнего обязательства, пересмотри. Команды и методология
берутся из проекта и назначения работы; отдельный процесс QA применяется по его правилам.
