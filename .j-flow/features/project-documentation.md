# Постоянные документы проекта

## Поведение

Каждый прогон проверяет описание проекта, state, индекс фич и checks. Недостающее
создаётся и в существующей частичной `.j-flow/`. Новый проект может не иметь кода или Git;
назначение известно из запроса, отсутствие реализации и команд указывается явно.
Существующие документы связываются ссылками с краткой картой и сохраняют своего владельца.

## Актуализация

Исполнители передают изменения устройства с источниками. На границах задач сохраняется
результат и точка продолжения. Перед финальным отчётом при любом статусе хранитель
актуализирует карту, state, затронутые функции и проверки. Контроллер проверяет комплект.
Недоступные сведения и незакрытая приёмка не становятся подтверждёнными фактами.

## Проверки

Проверка якорей охватывает project.md и features; режим пустой проверки нового проекта
выдаёт N/A и не скрывает битые якоря. Автотесты проверяют эти два наблюдаемых случая.
Сценарии поведения агента проверяются на пустом проекте, частичной документации существующего
проекта и незавершённой приёмке после изменений. Ограничения результата записываются отдельно.
