# Выбор документов и ревью

## Источники правил

`SKILL.md` содержит общую политику и таблицу «Ресурсы по ситуации».
Поддерживающие документы уточняют отдельную технику, их условия не являются списком
обязательного чтения. Контроллер выбирает ресурс по этапу или симптому, роль получает
свой бриф и шаблон. Применимая проектная тестовая политика передаётся в каждый бриф.

## Исполнение и доказательства

SDD описывает журнал, передачу задач, исправления и итоговое ревью. При отсутствии
делегирования те же этапы выполняет контроллер с явным указанием отсутствия независимого
ревью. Согласование решения не разрешает коммит автоматически.

Доказательства проверок относятся к версии кода и окружению. Неизменённое состояние
допускает использование результатов роли; затронутые изменения и конкретные сомнения
требуют новой проверки. Отдельная e2e-методология тестировщика не назначается всем тестам
разработчика по умолчанию.

## Помощники

`sdd-workspace` учитывает нормализованный путь плана; старый каталог возвращается
только при совпадении идентичности в первой строке журнала.
`task-brief` извлекает `Task N` из плана.
`review-package` поддерживает диапазон коммитов и режим `--working-tree -- PATH...`.
Новые файлы входят в пакет, чужие пути исключаются. Чужие изменения внутри общего файла
требуют исходной копии и явного ограничения области ревью.
Все помощники вызываются через Bash, включая внутренние вызовы.

## Проверка редакции

Проверка ссылок: нет отсутствующих ресурсов; все 15 документов `references/` имеют условие
выбора в основном маршруте. Восемь сценариев проверены независимым агентом на уровне
чтения и выбора инструкций; это не восемь реальных прогонов разработки.
26 Node-тестов прошли в Windows; десять проверяют поведение Bash-помощников в Git Bash.
Новая проектная установка из локального пакета и регистрация семи ролей проверены
в изолированной папке. Реальный клиент ZCode и native Unix этой редакцией не проверялись.
